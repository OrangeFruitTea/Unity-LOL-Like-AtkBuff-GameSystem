## 4.2.1 事件总线与接口契约

### 事件数据载体（`IGameEvent`）

每个业务事件类型实现 `IGameEvent`，由 `EventId` 表达语义，`Timestamp` 在首次 `Publish` 时可自动填 `DateTime.Now`，`Priority` 同时参与**调度队列**的排序键。

```csharp
public interface IGameEvent
{
    string EventId { get; }
    DateTime Timestamp { get; set; }
    GameEventPriority Priority { get; }
}

public enum GameEventPriority { Low = 0, Normal = 1, High = 2 }
```

### 订阅与广播（`GameEventBus`）

**数据结构**：`_eventHandlers : Dictionary<Type, List<GameEventHandlerInfo>>`，每项含 `Handler`（`Delegate`）、`Priority`、`IsAsync`、`Filter`。`Subscribe` 在加锁下追加后按 `Priority` **降序**排序；`Publish` 在**锁内**对当前列表 `ToList()` 得快照，**锁外**遍历，避免回调里改订阅表。

**分发规则**：`Filter != null && !Filter(eventData)` 则跳过；`IsAsync` 为真时用 `ThreadPool.QueueUserWorkItem` 调用 `Handler.DynamicInvoke(eventData)`，否则当前线程同步 `DynamicInvoke`。`PublishAsync` 则整次 `Publish` 放到线程池。

```csharp
public void Subscribe<T>(GameEventHandlerDelegate<T> handler, GameEventSubscriptionOptions options)
    where T : IGameEvent
{
    if (handler == null) return;
    var eventType = typeof(T);
    lock (_lock)
    {
        if (!_eventHandlers.ContainsKey(eventType))
            _eventHandlers[eventType] = new List<GameEventHandlerInfo>();
        _eventHandlers[eventType].Add(new GameEventHandlerInfo
        {
            Handler = handler,
            Priority = options.Priority,
            IsAsync = options.IsAsync,
            Filter = options.Filter
        });
        _eventHandlers[eventType].Sort((a, b) => b.Priority.CompareTo(a.Priority));
    }
}

public void Publish<T>(T eventData) where T : IGameEvent
{
    if (eventData == null) return;
    if (eventData.Timestamp == default)
        eventData.Timestamp = DateTime.Now;
    List<GameEventHandlerInfo> handlers;
    lock (_lock)
    {
        if (!_eventHandlers.TryGetValue(typeof(T), out handlers)) return;
        handlers = handlers.ToList(); // 快照，避免遍历时订阅表被改
    }
    foreach (var handlerInfo in handlers)
    {
        if (handlerInfo.Filter != null && !handlerInfo.Filter(eventData))
            continue;
        if (handlerInfo.IsAsync)
            ThreadPool.QueueUserWorkItem(_ => handlerInfo.Handler.DynamicInvoke(eventData));
        else
            handlerInfo.Handler.DynamicInvoke(eventData);
    }
}

public void PublishAsync<T>(T eventData) where T : IGameEvent
{
    if (eventData == null) return;
    if (eventData.Timestamp == default)
        eventData.Timestamp = DateTime.Now;
    ThreadPool.QueueUserWorkItem(_ => Publish(eventData));
}
```

`GameEventSubscriptionOptions`：`Priority`（默认 `Normal`）、`IsAsync`、`Filter : Func<IGameEvent, bool>`。`Unsubscribe<T>` 在锁内 `RemoveAll(h => h.Handler == handler)`。公开 API 名称应为 **Subscribe**、**PublishAsync**、**Filter**（勿与拼写错误如 Subscirbe、PublicAsync 混淆）。

### 调度与节流（`GameEventScheduler`）

**入队**：`Schedule(IGameEvent)` 在锁内 `_eventQueue.Enqueue(eventData, (int)eventData.Priority)`。工程内 `PriorityQueue<T>` 在 `Enqueue` 时向列表追加 `(priority, item)` 后**按 priority 降序排序**，故队首始终为当前最高优先级事件。

**延迟**：`ScheduleDelayed` 通过 `FindObjectOfType<MonoBehaviour>()` 找任意 `MonoBehaviour` 启动协程：`WaitForSeconds(delay)` 结束后再 `Schedule(eventData)`。

**出队与 Publish**：`ProcessQueue` 若 `_isProcessing` 则直接返回；否则置标志，在单线程循环中每次**抢锁 Dequeue 一条**，锁外调用 `GameEventBus.Instance.Publish(eventData)`。此处 `eventData` 静态类型为 `IGameEvent`，C# 会推断为 `Publish<IGameEvent>(eventData)`，总线用 `typeof(IGameEvent)` 取处理器列表；**仅 `Subscribe<MyConcreteEvent>` 的监听不会走这一条**，除非另有对 `IGameEvent` 的订阅或非泛型分发扩展。单轮最多处理 `_maxConcurrentEvents`（默认 10）。实现细节以仓库内 `GameEventScheduler` 类型为准。

```csharp
public void Schedule(IGameEvent eventData)
{
    if (eventData == null) return;
    lock (_lock) { _eventQueue.Enqueue(eventData, (int)eventData.Priority); }
}

public void ProcessQueue()
{
    if (_isProcessing) return;
    lock (_lock) { if (_eventQueue.Count == 0) return; _isProcessing = true; }
    try
    {
        for (int processed = 0; processed < _maxConcurrentEvents; processed++)
        {
            IGameEvent eventData;
            lock (_lock)
            {
                if (_eventQueue.Count == 0) break;
                eventData = _eventQueue.Dequeue();
            }
            GameEventBus.Instance.Publish(eventData); // 泛型实参推断为 IGameEvent，与按具体事件类型订阅的 handler 可能不匹配
        }
    }
    finally { _isProcessing = false; }
}

public void Update()
{
    if (UnityEngine.Time.time - _lastProcessTime >= _processInterval) // 默认 ~60Hz
    {
        ProcessQueue();
        _lastProcessTime = UnityEngine.Time.time;
    }
}
```

**节拍**：`_processInterval` 默认 `0.016f`，仅当帧时间与上次处理间隔足够才 `ProcessQueue`，形成**按时间片消化队列**，与同帧风暴解耦。

### 与 Unity 生命周期的桥接（`EventDispatcher` + `BasementUnityPump`）

`EventDispatcher` 在 `Awake` 初始化总线与调度器；`Update` 里若 `BasementLoopRouting.IsEcsPumpActive` 为真则**不**泵送（由 ECS 侧 `BasementPumpEcsSystem` 调 `BasementUnityPump.PumpUpdate` 统一驱动）；否则调用 `BasementUnityPump.PumpGameEvents()`。`OnDestroy` 时 `GameEventBus.Instance.Clear()`。

```csharp
// BasementUnityPump.cs
public static void PumpGameEvents() => GameEventScheduler.Instance.Update();

public static void PumpUpdate()
{
    PumpMatchTimeUpdate();
    PumpTimingTasks();
    PumpGameEvents();
}
```

```csharp
// EventDispatcher.cs（节选）
private void Update()
{
    if (BasementLoopRouting.IsEcsPumpActive) return;
    BasementUnityPump.PumpGameEvents();
}
```

### 发布方：立即广播 vs 先入队

| 意图 | 调用 | 行为 |
|------|------|------|
| 立即通知所有订阅者 | `GameEventBus.Instance.Publish(new SomeGameEvent { ... })` | 当前线程（或选项异步）直达 handler |
| 削峰、按调度节拍合并感 | `GameEventScheduler.Instance.Schedule(new SomeGameEvent { ... })` | 先入优先级队列，由 `Update`/`PumpGameEvents` 触发 `ProcessQueue` 再 `Publish` |

示例（与工程习惯一致）：

```csharp
GameEventBus.Instance.Initialize();
GameEventBus.Instance.Publish(new CombatUnitDiedGameEvent { /* ... */ });

GameEventScheduler.Instance.Schedule(new SomeQueuedEvent { /* ... */ });
```

### 可选增强（同一 Events 模块内按需接入）

- **去重**：在 `Publish` 前使用 `EventDeduplicator`：若 `ShouldProcessEvent(ev)` 为假则跳过本次分发，避免短时间重复事件刷屏或重复副作用。
- **批处理**：`BatchEventProcessor` 在条数或超时达到阈值后，对积累的事件逐个调用 `GameEventBus.Instance.Publish`，减少帧内调用次数。
- **对象池**：`EventPool<T>.Get()` 与 `Return` 复用事件实例，降低高频构造与 GC 压力。

## 与可观测性设施的职责划分

**事件分发**解决模块间**松耦合通信**。运行期**可观测性**另由日志、诊断 UI 等承担（例如工程里的 `LogManager`、Editor 下的 `EventDebugWindow` 通过展示队列大小或清空队列辅助调试）：两类能力解耦。监听器可在 **Subscribe** 的 handler 内自行打日志或把数据推到调试 UI，但**不应**把具体日志或窗口实现嵌进 `GameEventBus` 的遍历路径，以免 Basement 层与展示层缠在一起。

## 附：队列路径与订阅键

`GameEventBus` 以 `typeof(T)` 为键存订阅表。`Schedule` → `ProcessQueue` 中持有的引用静态类型为 `IGameEvent`，因此 `Publish(eventData)` 被编译为 **`Publish<IGameEvent>`**，只匹配键 `typeof(IGameEvent)`。**先入队再广播**要与已有 `Subscribe<MyEvent>` 对齐，需要：`Subscribe<IGameEvent>`、或对总线增加「按运行时 `eventData.GetType()` 向上查找并调用各具体类型处理器」的分发逻辑；否则队列吐出的消息可能到不了只订阅具体类型的 handler。对比之下，**立即路径**写 `Publish(new MyEvent())` 时泛型为 `MyEvent`，与 `Subscribe<MyEvent>` 一致。
